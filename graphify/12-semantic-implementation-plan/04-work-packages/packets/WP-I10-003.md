## Canonical requirements (3)

- `CAN-LAM-AI-032` — When an AI task is recorded, Lamha must store the model identity with the task record and mark dependent output stale when the model changes. (source: 01-EVERYTHING-WE-ARE-KEEPING.md / lines 1668-1668)
- `CAN-LAM-AI-090` — Lamha MUST NOT prevent a user from selecting a stronger or higher-accuracy local AI model solely because estimated processing time is long or the hardware is weaker than recommended. After verifying that the model is technically compatible with the device, Lamha MUST show estimated processing time, memory use, storage use, power and thermal impact, and available acceleration. The user MUST be allowed to continue immediately, schedule the job, process selected folders only, or choose a lighter model. Lamha MAY block the model only for a hard technical incompatibility, including insufficient safe memory, insufficient storage, unsupported model operations, unsupported runtime/provider, invalid or corrupted model files, or unresolved licensing restrictions. (source: LAMHA AI MODEL CHOICE AMENDMENT / amendment-2026-08-06)
- `CAN-LAM-ARCH-394` — Content suggestions from the local worker must carry model, source, and configuration provenance and remain reviewable until approved. (source: 03-HOW-WE-WILL-KEEP-DELETE-AND-CHANGE.md / lines 1481-1481)
