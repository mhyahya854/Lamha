# Migration risks

Migration can lose parity if generated SDK consumers, DTO semantics, job/event behavior, server storage assumptions, auth-scoped queries, mobile-only behavior, current metadata, or deployment/runtime paths are missed. Slice-by-slice Tauri replacement, exact caller/consumer maps, baseline hashes, current tests, focused parity proof, reversible data migration, and safe early removal with final Phase 16 residue scans control the risk.
